# Организация работы агента: журнал, планы, локальные release notes

## Проблема

Найдено расхождение: в интеграционном проекте (Laravel-приложение на этом же клиенте) организация работы агента устроена
заметно лучше — есть `.agents/journals/` с картой сессий и файлами, `plans/` для многошаговых задач, локальные скилы и
явные правила ведения. В `max-php-client` ничего из этого не было, при этом:

- `AGENTS.md` разросся до 375 строк: две трети — справочник по API MAX, а не правила работы; раздел «Источник истины» и
  «Частые ошибки» дублировали то, что меняется отдельно от кода;
- статус в AGENTS.md устарел: указана v1.0.0, тогда последний тег v1.1.3, и «база истории» из трёх коммитов;
- 14 файлов `RELEASE_NOTES_v*.md` лежали в корне репозитория незакоммиченными — описания релизов v1.0.2…v1.1.5
  существовали только в рабочем дереве;
- `.agents/` существовал, но был пуст и не был в `.gitignore` — первый же `git add .` отправил бы рабочие заметки в
  публичный репозиторий на Packagist;
- не было правил журнала и планов, не было разграничения «попросили текст коммита / попросили закоммить»;
- в Gate и в CI не было `composer audit`, хотя пакет публичный.

## Решение

- `.agents/` сделан локальным рабочим набором и добавлен в `.gitignore`: `journals/JOURNAL.md`,
  `journals/sessions/`, `plans/`, `release/`. Release notes перенесены из корня в `.agents/release/`.
- Правила ведения `.agents` (формат файла сессии, статус плана, что нельзя писать в журнал) — в AGENTS.md, раздел 5;
  добавлены в правила агентов как обязательный пункт.
- Справочник API вынесен из AGENTS.md в `docs/api-reference.md`: процесс синхронизации со спекой, аутентификация,
  критичные оговорки, rate limits, вебхуки, схема-соглашения, таблица эндпоинтов, enums, DTO. Добавлен раздел «Что
  делать при расхождении спека vs реальный API» — таблица зафиксированных случаев (link.sender строкой, base64-хеш
  контакта, raw vcf_info, мс в join_time, фото-токен в `photos`).
- Gotchas оставлены в AGENTS.md (короткий чек-лист, нужен всегда), разделы перенумерованы, ссылки заменены на пути к
  `docs/api-reference.md`.
- Добавлено правило про коммиты по образцу интеграционного проекта: «напиши текст коммита» — вернуть HEAD, без
  `git commit`; «закоммить» — выполнить коммит. Плюс запрет `git add .` без проверки `git status`.
- `composer audit` добавлен в обязательный Gate (шаг 6) и в CI job `quality` после coverage-gate.
- В AGENTS.md §1 статус указывает v1.1.3 с отсылкой к `git tag` как к источнику истины; протухшая «база истории»
  удалена; в чек-лист добавлена синхронность `README.md` и `docs/api-reference.md` и обновление `.agents/`.
- README: ссылки на файлы release notes заменены на ссылки на GitHub Release (файлы теперь локальные, в публичном
  репозитории их нет).
- OWASP Top 10 (был только подразделом раздела 7) выведен в правила агентов как пункт 9 и в чек-лист «production-grade»
  как отдельная позиция — раньше он попадал в самопроверку косвенно.

## Нюансы

- Приватность: журнал нельзя коммитить — в нём прод-диагностика (значения полей, порты, имена хостов). Публичная
  истина — README, docs и GitHub Release; поэтому release notes не попадают в дистрибутив, а значимые пункты дублируются
  в README.
- Нумерация разделов AGENTS.md сдвинулась (Gate стал разделом 8), внутренние ссылки обновлены.

## Gate

PHP-код не менялся, но правило проекта требует прогон после правок в репозитории. Прогнано в Docker:
`composer run lint` (0 файлов с правками), `vendor/bin/phpstan analyse` (0 ошибок), `vendor/bin/phpunit` (все зелёные),
`composer run coverage` (≥95% строк), `composer audit` (0 уязвимых).
