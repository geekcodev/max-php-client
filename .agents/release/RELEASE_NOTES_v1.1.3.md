# v1.1.3 — ContactVerifier: хэш по сырым байтам vcf_info (CRLF)

## Исправления

### Контакт из кнопки `request_contact` не проходил проверку на реальных payload MAX

- `ContactVerifier::verify()` перед вычислением HMAC приводил все переносы строк в `vcf_info` к LF (`\r\n`/`\r`/`\n` →
  `\n`), исходя из предположения, что платформа подписывает LF-форму.
- Фактически MAX подписывает `vcf_info` **как есть** — сырые байты: vCard с реальными CRLF и концевым переводом строки
  после `END:VCARD`. Подтверждено на проде: `hash_hmac('sha256', rawVcf, token)` равен полученному хэшу
  (`match_raw=true`), а LF-нормализация даёт другое значение (`match_lf=false`), поэтому даже при корректном контакте
  бот отвечал «Не удалось проверить контакт».
- Теперь `verify()` в первую очередь считает HMAC по **сырым байтам `vcf_info`**. Для транспортов, которые оставили
  литеральные `\r\n` (двойное JSON-экранирование), восстанавливает их в реальные CRLF и пробует ещё раз. Сравнение всех
  вариантов — константное `hash_equals`. Хэш по-прежнему принимается в hex или base64 (стандартной/URL-safe, с паддингом
  и без).

### Затронутые сценарии

- `ContactVerifier::verify($vcfInfo, $hash)` — порядок проверки: сырые байты → восстановленный CRLF (только если в
  `vcf_info` присутствуют литеральные `\r\n`).
- Литеральные `\r\n` теперь приводятся к CRLF (а не LF, как в v1.1.1–v1.1.2) — в соответствии с фактическим
  подписыванием платформы.
- Никаких изменений сигнатур и DTO — обратная совместимость полная.

## Обратная совместимость

- Не breaking: затронута только внутренняя логика сравнения. Ранее работавшие сценарии (raw-LF payload) продолжают
  работать; добавлена поддержка real-CRLF payload, как их шлёт MAX.

## Качество

- PHP 8.4, PSR-12 (php-cs-fixer) — 0 замечаний; PHPStan level max — 0 ошибок.
- PHPUnit зелёные (233 теста, 565 assertions).
- Тесты контактной верификации перезаписаны под реальное поведение MAX:
  `it_verifies_contact_hash_over_raw_vcf_bytes`,
  `it_verifies_contact_hash_over_literal_crlf_restored_to_crlf`,
  `it_verifies_contact_hash_with_trailing_crlf_as_sent_by_max` (регрессия по прод-payload) + существующие
  hex/base64-тесты.
