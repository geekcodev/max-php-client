# v1.0.9 — токен изображения из словаря photos (21.08.2026)

## Исправления

### Загрузка изображений: token всегда был null

- Для `type=image` API MAX возвращает токен вложения **только в ответе шага 2** (загрузка файла на
  `iu.oneme.ru`), причём внутри словаря `photos`, а не в топ-уровневом поле:
  ```json
  {"photos": {"<hash>": {"token": "..."}}}
  ```
  Ответ шага 1 (`POST /uploads?type=image`) содержит только `url` — без токена.
- В v1.0.8 `Uploader` разбирал из ответа шага 2 только топ-уровневый `token`, поэтому для изображений
  `UploadResult::$token` всегда был `null`, и вложение нельзя было прикрепить к сообщению.
- Теперь `Uploader::upload()` извлекает токен из последней записи словаря `photos`, если топ-уровневый
  `token` в ответе шага 2 отсутствует (`src/Upload/Uploader.php`).
- Поведение подтверждено живым запросом к реальному API и официальной документацией (dev.max.ru → POST /uploads: «для
  type=image токен возвращается в ответе на загрузку файла»).

## Затронутые сценарии

- Загрузка изображений: `$result->token` теперь содержит рабочий токен для
  `AttachmentRequest::create(AttachmentType::Image, token: ...)`.
- Видео/аудио (токен в шаге 1), файлы и изображения с топ-уровневым `token` в шаге 2 — поведение не изменилось;
  приоритет источников: топ-уровневый `token` шага 2 → словарь `photos` → `token` шага 1.

## Обратная совместимость

- Не breaking: сигнатура `upload()` и поля `UploadResult` не изменились.
- Исправление только восстанавливает ожидаемое поведение, описанное в документации API.
