## Новое: извлечение номера телефона из контакта

`GeekCo\MaxPhpClient\Security\ContactPhoneExtractor::fromVcf(string $vcfInfo): ?string` — значение первого непустого
`TEL` из `vcf_info` контакта, возвращается как есть, без нормализации.

- Поддержаны реальные `CRLF`/`CR`/`LF`, литеральные `\r\n`/`\n`/`\r` после `json_decode`, свёрнутые строки vCard,
  регистронезависимое имя свойства и параметров, префикс группы (`item1.TEL`).
- `X-TEL` не является телефоном и не разбирается.
- Шаблон: `/^(?:[A-Za-z0-9-]+\.)?TEL(?:;[^:]*)?:(.*)$/i`.

Во входящем `ContactAttachmentPayload` поля `vcf_phone` нет, номер брать только из `vcf_info`, порядок в потребителе:
`$contact->vcfPhone ?? ContactPhoneExtractor::fromVcf((string) $contact->vcfInfo)`. В исходящем payload `vcf_phone`
присутствует.

Подтверждено на реальном payload от Android-клиента: `PRODID:ez-vcard 0.10.3`, `TEL;TYPE=cell` строчными, номер **без
`+`**, `TEL` раньше `FN`, завершающий CRLF после `END:VCARD`, 110 байт. Нормализация номера в библиотеке намеренно не
делается: подтверждён единственный реальный захват с российским номером, формат номеров других стран не установлен. Если
номер используется как ключ (CRM, дедупликация, лид), канонизацию выполняет потребитель.

Замена собственного разбора vCard в интеграционном проекте (i2tech, `RequestFlowService::telFromVcf()`) даёт два
выигрыша: разворачивание свёрнутых строк (без него длинный номер обрезается на переносе и попадает в базу обрезанным)
и регистронезависимость имени свойства (`tel:` вместо `TEL`).

Пример: `examples/verify-contact.php` — полный путь `Update::fromArray()` → `AttachmentType::Contact` →
`ContactAttachmentPayload` → `ContactVerifier` → `ContactPhoneExtractor`, с проверкой подписи и отклонением подменённого
номера.

## Новое: процесс проверки документации и релиза

Правки в `AGENTS.md` — процесс, а не поведение библиотеки:

- **Шаг 7 Gate — сверка документации**, выполняется всегда, а не только перед релизом: цифры из последнего прогона,
  правдивые отрицания, статус релиза равен последнему тегу на origin, публичный API описан в `README.md` и
  `docs/api-reference.md`, md-файлы без висячих ссылок, `.agents/` не попал в состав релиза.
- **Правило для проверяющих агентов:** утверждения о публикации проверять письмом Packagist и страницей пакета, наличие
  тега — через `git ls-remote --tags origin`, а не по косвенным признакам.
- **Неизменяемость опубликованных версий:** переставленный или force-pushed тег вызывает блокировку Packagist,
  довыпуск — только новым тегом с новым номером.
- Правило `/tests/Fixtures/vcard/*.vcf -text` в `.gitattributes` вынесено в отдельный блок с комментарием: без него
  фикстура с реальными CRLF молча конвертировалась бы в LF у клонировавших и тест на структуру payload падал бы.

Правило шага 7 введено по итогам v1.1.7, где документация расходилась с фактом в трёх местах подряд: устаревший номер
релиза в `AGENTS.md`, неверное имя фикстуры в плане и ложное отрицание о публикации на Packagist.

## Обратная совместимость

Публичный API не изменён: добавлен новый класс, `ContactVerifier`, DTO и существующие методы не тронуты. Правки
`AGENTS.md` и `.gitattributes` на поведение библиотеки не влияют.

## Безопасность

`ContactPhoneExtractor` не логирует и не бросает исключений: `vcf_info` и номер — персональные данные (OWASP A09),
логирование остаётся вызывающему коду. Секреты, `vcf_info` и payload колбэков не попадают в журналы и коммиты.
