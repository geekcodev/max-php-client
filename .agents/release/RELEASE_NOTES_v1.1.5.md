# v1.1.5 — `tolerantInt`: равнозначные формы числа и значение в ошибке

## Исправления

### `InvalidResponseException: Field "sender" must be an integer` на `message.link` (продолжение v1.1.4)

- v1.1.4 научил `LinkedMessage::fromArray()` принимать числовую строку, но на проде исключение продолжило возникать:
  `Json::tolerantInt()` отклоняет всё, что не `int` и не строка, прошедшая `FILTER_VALIDATE_INT`. Значение, которое
  присылает API в этом случае, осталось неизвестным — версия 1.1.4 его не показывала.
- Сообщение об ошибке теперь содержит фактическое значение: `Field "sender" must be an integer or a numeric
  string, got {"user_id":7}.` Значение обрезается до 64 байт, JSON кодируется без `JSON_UNESCAPED_UNICODE`, чтобы
  обрезка не разрывала многобайтовые символы. Неоднозначные значения (объект, массив, `bool`) по-прежнему отклоняются:
  подменять их нулём нельзя, это уже не то же самое число.
- `tolerantInt()` дополнительно принимает равнозначные представления целого числа, которые JSON позволяет встретить
  рядом с `int`:
    - целочисленный float (`277570130.0`) — приводится к int;
    - строка с пробелами по краям (`" 277570130 "`) — обрезается перед проверкой.
- «Почти числа» по-прежнему отклоняются: `5.5`, `"5.5"`, `"007"`, `""`, `"abc"`, `"99999999999999999999"`,
  `true`, массивы, объекты, а также float вне диапазона int (`1.0e30`).

## Обратная совместимость

- Не breaking: сигнатуры не менялись, `Json` — внутренний класс. Изменён только текст сообщения
  `InvalidResponseException` для `tolerantInt()` и расширен набор принимаемых представлений.

## Качество

- PHP 8.4, PSR-12 (php-cs-fixer) — 0 замечаний; PHPStan level max — 0 ошибок.
- PHPUnit зелёные (249 тестов, 600 assertions).
- Новые тесты: `JsonTest::it_reads_a_tolerant_int` (пробелы и целочисленный float),
  `JsonTest::it_rejects_a_non_integer_tolerant_value` (случай `huge float`),
  `JsonTest::it_reports_the_received_value_when_tolerant_int_fails`.

## Что дальше

- Если после обновления исключение сохранится, его текст покажет реальное значение `sender` — по нему нужно либо
  расширить `LinkedMessage`, либо зафиксировать расхождение в `max-openapi`.
