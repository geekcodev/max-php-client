## Вывод

Навык полезен как второй независимый источник жёстких ограничений. Внедрены безопасные проверки (long polling,
callback_id, 4000 символов); остальные находки — либо ожидают данных смоука, либо являются UX-валидацией, которую можно
добавить отдельным решением.

## Отложено (не забыть)

Владелец решил добавить эти клиентские проверки позже, отдельной задачей после серверного смоука. Пока их нет, запрос
уходит в API и отклоняется сервером.

- [ ] Лимиты клавиатуры: всего ≤210 кнопок, ≤30 рядов, ≤7 кнопок в ряду (≤3 для `link`/`open_app`/
  `request_geo_location`/`request_contact`) — проверка в `Keyboard` или `InlineKeyboardAttachmentRequestPayload`.
- [ ] `PhotoAttachmentRequestPayload`: `url` / `token` / `photos` взаимоисключающие — fail-fast на комбинацию.
- [ ] `InlineKeyboardAttachmentRequestPayload::$buttons`: минимум один ряд (в схеме `minItems: 1`).
- [ ] `POST /answers` ≤2 запроса/сек на чат: в клиенте нет `chat_id` у callback, нужен per-chat лимитер на стороне
  потребителя либо новый ключ лимита.
- [ ] После проверки сервером: подтвердить или убрать `POST /chats/{chatId}/members` («retired» по навыку, есть в схеме
  v0.0.34) и зафиксировать фактический HTTP-статус.
