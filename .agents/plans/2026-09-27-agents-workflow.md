# План: организация работы агента в max-php-client

Статус: завершён.

## Цель

Перенести в `max-php-client` подход к организации работы агента, который хорошо работает в интеграционном проекте
(Laravel-приложение на этом клиенте): локальный журнал сессий, планы многошаговых задач, release notes, разделение
AGENTS.md на правила работы и справочник API, единые правила ведения документации и Gate.

## Реализация

1. `.agents/` с каталогами `journals/sessions/`, `plans/`, `release/`; добавлен в `.gitignore` (локальный набор, наружу
   не отдаётся).
2. `RELEASE_NOTES_v1.0.2.md`…`v1.1.5.md` перенесены из корня в `.agents/release/`.
3. Из AGENTS.md в `docs/api-reference.md` вынесены: процесс синхронизации со спекой, аутентификация, критичные оговорки,
   rate limits, загрузка медиа, вебхуки, схема-соглашения, таблица эндпоинтов, enums, ключевые DTO. Добавлен раздел 9
   «Что делать при расхождении спека vs реальный API» — таблица зафиксированных случаев.
4. AGENTS.md: статус v1.1.3 вместо v1.0.0 с отсылкой к `git tag`; удалена протухшая «база истории» из трёх коммитов;
   добавлены раздел 5 «Рабочие каталоги .agents и docs» с правилами ведения, правило про коммиты (текст коммита против
   коммита), п. 9 про язык и стиль md, п. 7 про регрессии из интеграционных проектов; Gate дополнен шагом 6
   `composer audit`; чек-лист дополнен синхронностью документации и обновлением `.agents/`.
5. CI job `quality`: добавлен шаг `composer audit` после coverage-gate.
6. README: восемь ссылок на файлы release notes заменены ссылками на GitHub Release.

## Тесты

PHP-код не менялся, публичный API не затронут. Прогнан Gate в Docker: lint (0 файлов с правками), phpstan (0 ошибок),
phpunit (все зелёные), coverage (≥95% строк), composer audit (0 уязвимых).

## Нюансы

- Release notes локальные — публичная истина в README (раздел «История изменений») и в GitHub Release. Поэтому значимые
  пункты релиза дублируются в README, иначе они потеряются для потребителей.
- В журнал нельзя писать секреты, `vcf_info` и payload колбэков: журнал не коммитится, но и не должен содержать значений
  токенов, даже локально.
- Gotchas оставлены в AGENTS.md, а не в `docs/`: они короткие и нужны при любой правке кода, а не только при работе с
  API-контрактами.
